# 美术审查工作流（主美术的 QA 闭环）

风格质感不是靠生成环节"祈祷"出来的，是靠"基准 → 约束 → 审查 → 回填"的闭环维持的。本文件定义审查层怎么跑。

## 定位红线：实机演示图 = 内部审查标准，不对外展示

含 HUD 的整幅场景实机演示图（pixel-art-game-assets 产线）是**内部 QA 资料，不是游戏内容**：

- **用途仅三样**：① 生成端风格锚（`--reference-image` 锁风格）；② 审查端基准（palette_audit 的基准色板来源、逐张验收的对照标准）；③ 场景级审查的拼合目标参照
- **三不**：不进 Godot 工程、不作为游戏素材/宣传图对外展示、不进资产台账的"对外资产"栏
- 对外（进引擎/交付）的产物只有一种：`godot_assets/` 里经 godot_export 处理的资产精灵
- 成批的场景包（如九国 90 景）定位为**内部审查基准库**，供开发组对照风格与审查用，受众=项目组内部

## 三层防线回顾

1. **基准层**：`assets/` 风格锚图（廷根广场 + 贝克兰德证交所两张，覆盖广场/市政两类场景），每张 generate 必带 `--reference-image`；场景锚同时也是调色板基准来源
2. **约束层**：`art-direction.md` 主调色板（hex 锚 → prompt 用词）、九国注入块、通用后缀、godot_export 统一 64 色量化
3. **审查层**（本文件）：逐张人工验收 + `scripts/palette_audit.py` 客观审查 + 台账 + 修方回填

## 审查时机

- **逐张**：每次生成立即验（对照类别验收清单，如实报告偏差，偏差大按修方重跑）
- **每批**：一批素材（≥5 件）产出后跑 `palette_audit.py`，REVIEW/FLAG 逐件裁定
- **每场景切片**：拼合后对照"拼合整合六件套"（engine-handoff）审整体，再出审查报告（格式见 2026-08 金梧桐切片报告：素材清单→逐件验收→问题定级→skill 回填）

## 工具：palette_audit.py

```bash
python3 scripts/palette_audit.py <素材目录> \
  --anchor assets/style-anchor-backlund-exchange.jpg \
  --anchor assets/style-anchor-tingen-square.png \
  --sheet <审查图输出.png>
```

度量逻辑：资产主色（alpha>100 像素 5bit 分箱前 5）到基准色板（主调色板锚 + 锚图主色）的最近欧氏距离。全过 → PASS；1 个超差 → REVIEW；≥2 → FLAG。

**判定 ≠ 结论**。FLAG 只表示"提请主美术裁定"，三种典型去向：
1. **基准缺口**：资产正确但基准缺这个色系（2026-08 实例：邮筒红、肤色被误 FLAG → 色板回填两锚）。处理：基准补锚，重跑转 PASS
2. **合法例外**：vfx/神秘道具的 22 途径专属色（beyonder-items 主色表）、他国专属调色板、食物色系——这些类别审查时按各自色表审，不用全局基准
3. **真实漂移**：色偏、脏色、风格软化——按该类别修方重跑

## 审查闭环（skill 自我修正的机制）

每次审查的结论必须落到以下一处，否则审查没有发生：
- prompt 问题 → 对应 references 的"修方"节加一条（已积累：视角前置、屋顶公式、opaque tile、帧条切帧、噪点地板……）
- 规格问题 → art-direction 尺寸表/调色板修订（如 building_l 档、门洞规则、肤色锚）
- 工具问题 → scripts/ 修订（如 tile 水印镜像修复、噪点清零）
- 台账记录 → `assets/asset-registry-template.csv` 登记 id/类别/国家/prompt/验收状态

## 审查不能自动化的部分（明说）

palette_audit 只管色彩家族。以下仍靠逐张人验：块状硬边像素感（有无软笔触）、视角（未漂 3/4）、国家识别物命中、文字错误、帧间一致性、比例关系（对照尺寸表）。工具负责筛出可疑件，人负责裁定。
